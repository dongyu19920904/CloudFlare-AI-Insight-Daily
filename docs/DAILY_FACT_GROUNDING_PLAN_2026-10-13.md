# 10 月 13 日 Meta 错配：调查与最小修复计划

## 目标与边界

先确认补图与 Meta 更正仍在线，再追溯原始缓存、提示词输入、生成和校验。保护原目录的分叉和用户改动，在 D 盘独立 worktree 工作。不改 UI、商机、定时、模型线路或 8192 输出预算，不给全部新闻增加第二轮模型审稿。

## 已确认的链路

`数据源 → KV 原始缓存 → dailyPromptSelection 的 Content Summary → buildDailyGenerationPromptInput → 正文模型 → 格式/结构校验 → 可选媒体后处理 → 发布`。

生成时不会因正文附有链接就自动读取链接文章。新补图流程在成稿校验之后，不能追溯为正文生成提供依据。publishValidation 当前不接收原始素材，所以不能判断产品类别是否与原文相反。

## 待验证的假设

1. 缓存只有标题、原链接和 HN 讨论数字，没有文章内容，模型在强制扩写时猜测了类别。
2. 聚合源拆分错误，标题/链接与其他条目正文混配。
3. 输入正确但生成模型错误联想；原有真实性规则未被遵循。

区分已证实事实与推断，不把模型内部联想冒充可观测日志。保存当天缓存和实际提示词作为复现证据。网络受限时用仓库现有只读检查 workflow，不触发正式生成或改写 KV。

## 最小实施顺序

1. 只读检查 workflow 留存公开缓存，回放候选构造，定位原词首次出现的位置。
2. 针对实际缺口补测试，再改最小责任模块。优先修复采集正文缺失与每条事实边界；不靠全局拒绝发布、硬编码某产品或关键词黑名单。
3. 如果某类候选确实只有讨论元数据，限量获取该篇真实标题/正文摘录，并明确标记材料来源与不足。原文无法取到时只能使用原题明示信息或更换其他候选，禁止从产品名猜能力。
4. 保留现有完整来源和长文正文，避免新摘要覆盖好素材。所有额外请求有数量、超时与响应大小上限，单站失败不拖住整篇日报。
5. 生成提示词只增加简短、针对性约束：标题不等于正文；讨论热度不是能力证据；不得从名称猜类别或补状态。
6. 运行回归测试与最终代码完整 dry-run，逐条核对 Meta 和其他只有标题的条目。不覆盖已修好的线上文章。通过后按原 SSH 与 Worker 部署流程发布代码。

## 验收

- 固定的错误输入能复现原提示词缺口，修复后原文的智能体类别与关键事实进入实际模型输入。
- 没有原文时不会把 HN 点赞/评论当作产品功能证据。
- 完整预览有真实来源支撑，不再出现音乐生成误写；图片、趣闻和 FAQ 不回归。
- 原定时、其他栏目和发布失败边界不变；记录额外网络/token 消耗及未能覆盖的风险。
