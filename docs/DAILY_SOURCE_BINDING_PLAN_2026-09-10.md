## 已复现的问题

上一阶段未发布试稿 `D:\GitHub\_artifacts\daily-link-readability-20260910\daily-preview.md` 中，第七条 DeepSeek 新闻使用了第四条 Omnii 的社媒来源，图片也变成了 Omnii。来源作者相同不代表事件相同。

真实链路：`buildDailyPromptSelection` 提供素材 → 模型生成正文/链接 → `repairDailyMediaReferences` 按链接寻找素材 → `ensureDailyMediaCoverage` 补图 → 摘要 → 原有校验/有限 repair → 发布。

问题不是图片 CDN，也不是字体或 Markdown 链接边界调整。模型先串了来源；媒体函数只核对 URL，不核对事件，进一步放大错误。没有图片的素材也必须参与来源检查。

## 最小改法

1. 保留结构化来源记录，包括本次入选正文和趣闻的 title、url、description、plainText，不从生成后的正文猜来源。社媒候选补上原始标题，减少同一作者不同帖的混淆。
2. 提示词增加一条明确约束：同一个候选内的事实、URL、图片是绑定的；相同作者不能互换；源文中的转述仍须保留证据边界。不额外改写整套提示词。
3. 在初稿和已有 repair 的补图之前，增加保守的串线隔离。仅当标题包含至少两个明确的英文实体/版本线索、已链接素材完全不含这些标题线索、另一个入选素材的正文匹配至少两个实体/版本线索（至少一个来自标题）、而当前素材具有正文未提及的另一实体时，隔离该条全文。社媒标题可能只是评论开头，因此核对结构化原文摘要，不要求标题一定含产品名。不能凭相似度自动换链接或制造事实依据。
4. 不确定、中文简称、对比文章、未知外部链接不靠这个规则判错；记录本规则局限，不宣称完成事实核查。FAQ 不参与新闻实体检查。
5. 只隔离问题条目，正常条目正文保持原文；发生 TOP 隔离时就地重排编号和实际条数，避免跳号。已有一次 repair 负责尝试补足。新检查不抛异常、不增加硬性整篇校验、不新增 AI/网络调用。若有效条目确实少于原有安全下限，仍执行现有发布策略，不为了发布放行错误内容或擅自降低下限。
6. 独立趣闻同样检查；失败仅放弃该趣闻。调试信息区分初稿、repair 和趣闻隔离数及来源 URL。
