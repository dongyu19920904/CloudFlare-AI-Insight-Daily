# AI 日报正文 Emoji 最小试点方案（2026-09-26）

## 现状与目标

- 对照 2026-09-26 的 hex2077 日报：26 条资讯的标题保持纯文本，正文每条各有一个与事实相邻的 emoji。它承担扫读标记，不替代事实、来源或判断。
- 爱窝啦同日原始日报有 16 条三级标题资讯，正文没有 emoji；现有图标主要在二级栏目标题。现行稳定提示词已规定黄色短结论、蓝色证据链接和正文句长，不应推翻这些规则。
- 目标是在普通资讯正文自然加入有明确语义的 emoji，使页面更易扫读；不追求每条强制覆盖，不牺牲准确性或正常发布。

## 实施范围

1. 仅在 `src/prompt/summarizationPromptStepZero.js` 的“重点标记”附近加入一条规则：普通资讯正文默认最多一个 emoji，贴近可由来源支持的产品、能力、风险或结果。没有合适符号，或涉及严肃伤害、未经证实的消息时可以不加。
2. 三级标题、来源链接锚文本、模型/数字、图片说明、FAQ 和系统单独生成的今日摘要保持原样；emoji 不算黄色重点，不用来暗示未经证实的发布、增长、盈利或政策落地。
3. 在 `tests/summarizationPromptStepZero.test.mjs` 增加提示词契约测试，防止规则被未来改稿意外删去。不得添加“缺 emoji 则拒绝发布”的硬校验或独立后处理。
4. 不修改前端、定时路由、模型配置、采集、AI 商机或 AI 账号商机。

## 验证与发布

- 运行针对性测试、完整 Node 测试和 Wrangler 打包 dry-run；检查 diff 仅含本方案、提示词与测试。
- 用 2026-09-26 已发布条目试写几条，核对图标是否贴合事实、是否挤占黄色重点或使句子更长。试写仅展示效果，不覆盖当天文章。
- 若具备安全的非发布模型 dry-run 入口和密钥，再生成一次样稿并人工检查；否则明确记录未做模型实测，不为测试触发正式日报。
- 测试通过后从独立工作区经 SSH 推送，检查 Worker 自动部署；次日核对真实产物的 emoji 位置、事实准确性和日报正常发布。预计只增加少量提示词 token，不增加 API 请求次数。
