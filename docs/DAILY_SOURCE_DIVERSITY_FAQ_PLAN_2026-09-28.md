# 2026-09-28 AI 日报来源多样性与相关问题修复

## 现状与根因

- 线上 `daily/2026-09-28.md` 的正文跨栏目引用 `t.me/aigc1024` 九次；这九个 URL 的文章 ID 不同，但发布频道相同。现有候选选择按 news/project/socialMedia/paper 配额和事件去重，没有发布者配额，模型收到多条同频道候选后把它们写进 TOP、产品栏目和趣闻。
- 候选的新闻输入不包含 `Source` 行；提示词示例鼓励“频道/作者在推文中介绍”式起句，形成同质前缀。模型无法用“链接不同”推断发布者应只出现一次。
- 配图只对来源 HTML 中可用的真实媒体给优先级；不能为无图频道稿配无关图片。来源多样化后，继续保留现有的真实图片匹配与修复规则。
- `dailyShopFaq.js` 只验证并保留已写出的 FAQ，不会创建缺失的 FAQ。主正文和修复提示都把它列为可选，于是 9 月 28 日结尾没有“相关问题”。

## 最小实施

1. 在 `dailyPromptSelection.js` 的候选入口建立稳定发布者键：Telegram 按频道、X 按账号、普通网站按站点；GitHub 日榜按仓库，避免把整个 GitHub 误算成一个新闻源。每个发布者只进入一个主候选；选其得分最高、证据较好且有真实媒体的候选。趣闻备用素材也不得与主候选复用同一发布者。把来源写入新闻/社媒候选输入，并记录源去重数量。
2. 在日报写作提示词中移除机械“据频道称”范例，要求以可核实变化起句；转述只能写成观察，产品状态优先指向官方。只有真实媒体可配图，不能为了图而猜。
3. 若主正文通过校验却没有 FAQ，从已入正文的一手/官方来源中选一条，做一次短篇非阻塞补写；只准引用该来源，执行现有主站链接白名单和全文校验。没有合格来源、模型报错或补写不合格时原正文照常发布。
4. 补充来源识别、同源优选、趣闻隔离、FAQ 缺失补写/失败不阻塞的单测；运行全套 Node 测试和 Wrangler dry-run。先不覆盖 9 月 28 日已发布文章。

## 边界与验收

- 候选不足 10 条时不得把同源弱稿塞回凑数；现有基于可用候选数量的最低 TOP 规则继续生效。若当天确实没有多源材料，应在日志中看见源去重数量。
- 不改定时 cron、发布目标、AI 商机或账号商机链路；额外模型调用仅在正文缺 FAQ 且存在合格来源时发生，失败不升级成日报失败。
- 不承诺每天都一定有 FAQ 或图片：证据不足时宁缺毋滥。商店链接只取当天核实过的 sitemap 目录，不推断商品价格、库存或套餐权限。
