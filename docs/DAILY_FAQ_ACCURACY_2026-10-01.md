# 相关问题最小修复方案

## 目标与边界

保留 2026-10-01 的一问、简短直接答案、一个官方来源、一次相关商品目录入口。修正“公告未说明套餐”与公告末尾说明开放顺序之间的矛盾。只调整普通日报的 FAQ 输入与提示词，不改变 cron、模型线路、TOP 选题、商机任务和失败隔离。

## 已检查的问题

- 主日报候选会压缩正文，FAQ 补写又只保留来源前 1400 字符，公告末尾的开放条件可能丢失。
- FAQ 提示词偏向“说明不能推断所有套餐”，容易把真实的阶段性开放计划写成“官方没有说明”。
- 官网目录白名单、最多一个商店链接、FAQ 的限时与异常隔离已经存在，应保留。

## 修改

1. 在所选官方来源 URL 与缓存原文精确匹配时，单独给 FAQ 保留原始正文。最多 6000 字符；超长时保留开头和结尾并明确标记省略。
2. 正文生成与独立补写共用这份 FAQ 证据；要求先回答已知结论，区分当前可用、受邀试用、未来开放及尚未确定的时间。
3. 单问、2-3 个短句；有具体套餐就准确命名，不用泛泛的“请向官方确认”代替答案。不猜主站商品的模型权限。
4. 修正今日日期稿、daily 存档及首页镜像中的这一段，其他内容和 UI 保持原样。

## 验证与发布

- 覆盖公告末尾开放范围、超长原文保留结尾、非官方素材保持原样、目录与主题关联、FAQ 超时不阻塞的测试。
- D 盘缓存下运行 Node 全量测试和 Hugo 构建。
- 使用当前模型生成 FAQ 试点，阅读完整日报 dry-run；正式稿仅更新已核实的 FAQ。
- SSH 推送并按现有 GitHub Actions 部署；核对 Worker 版本、页面和主站链接。
- 回滚只撤销本轮提交。不能保证未来每次生成的文笔，但必须报告实际预览、事实依据和未通过项。

## 真实预览发现与修正

第一次完整预览后检查实际缓存，发现 Google 官方文章 URL 对应的 content_html 只是 Hacker News 的 Comments URL、Points 和评论数。URL 属于官网，不等于缓存正文就是官方公告。增加最多一次、5 秒限时的官方文章正文读取；只用于 FAQ。失败时排除讨论元数据，保留真正的缓存事实；不影响日报发布。补充 GoogleAI 官方社媒账号识别，允许其原始公告中的受邀开放条件支持购买前问答。

## 实测结果

- 后端全量 440 项测试通过；前端 17 项测试通过，Hugo 构建成功。
- 第二轮真实模型预览：Actions 36819844526，使用当天缓存及当前主模型；官方正文包含末尾的 paid API customers 和 Google AI Ultra subscribers，生成的独立 FAQ 与完整日报 FAQ 均正确区分受邀试用和后续开放。
- 完整日报 dry-run 可发布、未正式发布、未写线上 KV；全篇仍有个别生硬句式，不能只凭校验通过就认为文笔优秀。因此正式稿保留今天既有正文，只修改 FAQ 答案，不替换 TOP、趣闻或其他模块。
- 浏览器检查桌面与手机日夜模式，FAQ 无横向溢出，canonical 正确；未修改 CSS、字体或 UI。
- 消耗变化：FAQ 选中官方网页时最多新增 1 次抓取，超时 5 秒；补充有上限的原文输入，不新增模型调用。既有 FAQ 独立补写与限时隔离保留。未来来源内容与模型文笔仍有波动，不能承诺每次都达到主观满意。
