# AI 日报 human-writing 最小融合方案

日期：2026-08-06

## 目标

在不改变 AI 日报栏目、来源选择、TOP 数量、Markdown 结构和定时发布链路的前提下，吸收 `KKKKhazix/human-writing` 中适合短篇资讯的写作原则，减少同义反复、模型套话和超过证据强度的标题，让每条内容更具体、更好扫读。

## 当前边界

- 基线：`origin/main` 的 `7dcd6bfff86cfa1c4c78b8dd71167f5699f82d9f`。
- 工作区：独立 D 盘 worktree，不修改严重分叉的原目录。
- 只处理普通 AI 日报，不修改 AI 商机、AI 账号商机、AI 趣闻独立生成器或 BioAI。
- 不把完整 Skill 或 Python 检查器放进 Cloudflare Worker。
- 不新增模型调用，不让风格问题阻止日报发布。

## 实施步骤

1. 将 `human-writing` 固定在 `v1.1.0` 安装为本机 Codex Skill，用于人工试写与复核，不跟随 `main` 自动更新。
2. 在普通日报主提示词中加入适配后的短规则：
   - 每句话必须新增事实、动作、区别、影响或读者动作。
   - 标题强度不得超过素材，明确区分已开放、测试、预告、愿景和转述。
   - 不虚构亲历、现场、效果、因果或用户反应。
   - 用具体角色和动作替换“值得关注”“这意味着”等空泛收尾。
   - 保留现有标题、链接、图片、FAQ 和短篇栏目格式，不采用禁用全部冒号、列表或破折号的长文规则。
3. 增加纯 JavaScript 的轻量风格审计：
   - 忽略 front matter、代码块、链接目标和媒体标签。
   - 仅检测重复套话、密集模型黑话和重复判断模板。
   - 结果只进入 `warnings`，不触发修复重试，不改变 `validation.ok`。
4. 添加单元测试，固定以下行为：
   - 提示词包含事实状态、逐句推进和禁止虚构规则。
   - 冒号、Markdown 链接和日报固定结构不会被误判。
   - 风格告警不阻断一篇结构与事实校验合格的日报。
5. 使用 `D:\CodexCache` 运行 Node 测试；再用线上 2026-08-06 Markdown 做只读审计样本。

## 验收标准

- 现有测试全部通过。
- 新测试证明风格告警不会令 `validateDailyPublication().ok` 变为 `false`。
- `generateDailyMarkdown` 调用次数和定时路由不变。
- TOP 10、专业栏目、来源链接、图片与 FAQ 规则不变。
- 线上样本能识别重复套话，但不会因正常冒号、URL 或结构化 Markdown 失败。

## 发布与回滚

- 测试通过后再提交并通过 SSH 推送专用分支；未经确认不覆盖当天线上日报。
- 回滚只需撤销本次提交。由于没有数据迁移、绑定或定时路由变化，不涉及额外恢复步骤。
